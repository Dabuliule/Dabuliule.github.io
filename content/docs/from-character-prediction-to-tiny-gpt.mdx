给出“我今天喝”，模型续写“茶。”；给出“他今天喝”，模型续写“水。”。这样一个小任务，足以把 Embedding、序列记忆、Attention 和 Transformer 放到同一条计算链中。

关键不在于把组件逐个装上去，而在于每次都回答：旧方法缺少什么信息？新增计算怎样提供这些信息？实验是否真的支持预期？

本文沿着一个字符续写实验逐步修改模型。句子中的人物偏好是人为约定的训练规则，不代表自然语言里存在唯一正确的续写。完整公式与独立组件的说明可参考[从 Token 到文本生成](/docs/from-tokens-to-transformer-generation)；这里重点解释组件之间的衔接。

## 实验范围与运行方式

最终模型是两层、四头、特征维度为 32 的因果 Transformer，使用可训练的位置向量，支持逐层 KV Cache。它从随机参数开始训练，不加载预训练模型。

下载[完整训练脚本](/examples/text-completion/train.py)和[训练语料](/examples/text-completion/corpus.txt)，保存到同一个目录。使用 Python 3.11 和安装了 PyTorch 的环境运行：

```bash
python train.py
```

脚本使用 CPU、单线程、随机种子 42、Adam、学习率 0.01，训练 300 轮。不同 PyTorch 版本和运行环境可能产生数值差异。这个实验用来理解计算，不用来证明模型具备通用语言能力。

下面用 $B$ 表示 batch 大小，$L$ 表示本次输入长度，$P$ 表示已缓存长度，$D$ 表示特征维度，$N$ 表示词表大小。代码片段用于解释局部变化，完整实现以下载的脚本为准。

### 阅读时始终跟踪三件事

这篇文章较长，可以分三段阅读：第 1～4 节解决“前文如何进入模型”；第 5～7 节解决“如何读取和加工前文”；第 8～11 节把训练、生成、验证和架构名称完整接起来。

每次出现新组件，都跟踪三个问题：

1. **参数是什么？** 它们由优化器更新，例如 Embedding 表和 Q/K/V 的线性层权重。
2. **中间结果是什么？** 它们由当前输入算出，例如隐藏状态、门值、Attention 权重和 KV Cache。
3. **信息能从哪里来？** 当前字符、过去的位置、独立的源序列，还是被错误暴露的未来答案。

分清这三件事，就不会把“状态有记忆”误解为“每句话都直接改了权重”，也不会把“缓存了历史”误解为“旧 K、V 已经不再重算”。

## 1. 只看一个字：模型只能学习相邻关系

先把每个字符当作一个 token。词表负责把字符映射为编号，Embedding 再按编号取出参数表的一行：

```python
embedding = nn.Embedding(vocab_size, 16)
vectors = embedding(input_ids)
```

编号只是索引，没有大小或语义含义。向量最初随机初始化，在预测任务的 loss 作用下，与其他权重一起更新。

最简单的模型只看最后一个字：

```text
“我喝” → 实际输入“喝” → 预测下一个字
“他喝” → 实际输入“喝” → 预测下一个字
```

如果语料分别要求“茶”和“水”，两个完全相同的输入就对应了不同答案。训练再久，也无法靠这个输入区分人物。

这个问题首先是信息缺失，而不是优化器不够好。

### 把“变成向量”拆成真正发生的两步

假设词表中的一部分是：

```python
token_to_id = {"我": 0, "他": 1, "喝": 2, "茶": 3, "水": 4}
```

为了方便展示，暂时把向量维度缩成 3。Embedding 内部就是一张参数表，初始数字可能类似：

```text
编号0（我）：[ 0.2, -0.5,  0.1]
编号1（他）：[-0.3,  0.8,  0.4]
编号2（喝）：[ 0.6,  0.2, -0.7]
编号3（茶）：[-0.1,  0.3,  0.9]
编号4（水）：[ 0.4, -0.2,  0.5]
```

调用 `embedding(torch.tensor([2]))`，取值上就是取 `embedding.weight` 的第 2 行。它不会分析“喝”的字形，也不是对整数 2 做某种语义运算。

随后 `Linear(3, N)` 把这个向量映射成词表分数。分数经过 softmax 后才是概率；训练时直接把分数交给交叉熵即可。

```text
“喝” → 编号2 → 取第2行 → 线性层 → 各字符分数 → 与“茶”的编号算 loss
```

反向传播会从 loss 回到线性层，再回到被查出的那行参数。向量并不是预先写好的知识，而是在任务中逐渐调整的表示。相同字符出现在多个样本中，对同一行产生的梯度会累加。

### 为什么相同输入不能同时答对两个相反目标？

假设训练中“喝”后面出现茶、水的次数相同。模型只接收“喝”，因此两条样本会得到相同的概率分布。

如果把茶的概率从 50% 调到 90%，要求茶的样本 loss 会下降，但要求水的样本 loss 会升高。模型没有人物信息，就无法为两条样本分别作出决定。这解释了为什么后面要修改输入，而不是单纯增加训练轮数。

## 2. 拼接两个字：把判断所需的信息送进去

让模型同时看到最近两个字：

```python
vectors = embedding(context_ids)       # [B, 2, 16]
joined = vectors.flatten(start_dim=1)   # [B, 32]
logits = output(joined)                 # [B, N]
```

`flatten(start_dim=1)` 保留 batch 维，把一个样本内部两个字的向量按顺序拼起来。预测层现在能同时使用人物与动作。

这里不是“神经网络每个样本只能接收一个向量”，而是当前设计选择了先拼接，再用一个线性层综合多个位置。直接对 `[B, 2, 16]` 使用 `Linear(16, N)`，只会分别处理两个位置，并不会自动让它们交流信息。

两字窗口可以区分“我喝”和“他喝”，但句子稍微变长：

```text
我今天喝 → 窗口里只剩“天喝”
他今天喝 → 窗口里只剩“天喝”
```

问题又回来了。扩大到四字窗口能处理这一组句子，却处理不了更远处的人物；而且 `Linear(C * 16, N)` 的参数量会随窗口长度 $C$ 增长。

### flatten 改变的到底是什么？

仍用三维示意向量，“我喝”的 Embedding 是：

```text
一个样本内部：
[
  [0.2, -0.5,  0.1],   ← 我
  [0.6,  0.2, -0.7]    ← 喝
]
```

flatten 后成为：

```text
[0.2, -0.5, 0.1, 0.6, 0.2, -0.7]
 └──第一个位置──┘ └──第二个位置──┘
```

元素没有被平均，也没有相加，位置顺序仍然体现在向量的不同区段。后面的线性层可以给不同区段设置不同权重。

扩展窗口的成本也可以精确算出来。字符向量维度为 $D$、窗口长度为 $C$、词表大小为 $N$ 时，输出线性层的参数量是：

$$
N(CD)+N
$$

最后一项是偏置。窗口扩大一倍，这一层的权重数量也扩大一倍，而窗口以外的信息仍然不可见。接下来寻找的，是一种能反复使用同一组参数处理序列的方法。

## 3. RNN：逐字更新一份固定长度的记忆

一种替代方案是，不再拼接整个窗口，而是每读一个字就更新状态：

$$
h_t=\tanh(W_xx_t+W_hh_{t-1}+b)
$$

```python
h = vectors.new_zeros((batch_size, 32))
for position in range(length):
    x = vectors[:, position, :]
    h = torch.tanh(input_to_hidden(x) + hidden_to_hidden(h))
logits = output(h)
```

`h` 是根据输入和权重算出的中间结果，不是直接存储的可训练参数。各个位置复用同一组权重，因此多读几个字会增加计算次数，但不会为新位置增加一套 RNN 参数。

例如读“我喝”：

```text
“我” + 零状态 → h₁
“喝” + h₁    → h₂ → 预测“茶”
```

`h₂` 不只是“喝”的表示，还可能携带“我”的信息。把“我”换成“他”，“喝”的 Embedding 不变，但旧状态不同，新状态也可能不同。

### 为什么旧 h 还要经过一次线性变换？

`W_x x` 把当前输入映射到隐藏维度，`W_h h` 则让模型学习怎样组合旧信息。即使旧 `h` 已经是 32 维，也不意味着应该原样加到新状态里。

例如旧状态为 `[2, 3]`，某个线性变换可以得到：

```text
第一个新分量 = 0.5 × 2 + 0 × 3 = 1
第二个新分量 = 1 × 2 - 1 × 3   = -1
```

模型可以放大、减弱或混合不同分量。直接相加相当于固定使用单位变换，限制更强。偏置则提供与输入无关的基准偏移，使更新不必经过原点。

### h 怎么学会携带人物信息？

模型没有收到“第 3 维必须记人物”的指令。它只收到两类预测要求：

```text
我今天喝 → 茶
他今天喝 → 水
```

如果两条前缀最终变成一样的 `h`，预测层就无法同时区分它们。loss 的梯度沿着状态更新链回传，推动参数形成能保留这种区别的计算方式。

这是优化目标施加的压力，不是一定成功的保证。信息可能分布在多个维度里，也可能在训练不足或距离太长时没有保留下来。

### 记忆是否真的被利用？

在一个已经训练好的小实验中，完整读取“我今天早上喝”和“他今天早上喝”时，模型分别倾向于茶和水。在读最后一个“喝”之前把 `h` 清零，两种输入就得到完全相同的预测分布。

原因很直接：当前字相同、旧状态都是零、权重相同，计算结果必然相同。这个干预说明前文通过状态影响了预测，不代表状态完整保存了原文。

### 为什么还要 tanh？

如果删除 `tanh`，反复的线性变换与相加仍能展开为各输入向量的线性组合。模型并不会因此无法运行，预测层也仍然需要把隐藏维度映射到词表分数；但状态更新的表达方式受到限制。

`tanh` 加入非线性，也把状态各分量限制在 −1 到 1 之间。它本身不储存记忆，记忆来自状态跨步骤传递。

### 没有 tanh，预测层是不是就“没用了”？

把一个步骤简化成标量计算：

```text
新状态 = 2x + 3h + 1
分数   = 4 × 新状态 + 5
       = 8x + 12h + 9
```

这次计算中的两个线性变换可以合并，但不等于预测层的乘法和偏置没有作用。真实模型里，隐藏状态还要递归传给下一步，而且隐藏维度与词表维度通常不同，不能在不改变模型的情况下直接删掉预测层。

加入 `tanh` 后：

```text
分数 = 4 × tanh(2x + 3h + 1) + 5
```

就不能再整理成关于 `x` 和旧 `h` 的单个仿射变换。它允许状态变化依赖当前数值所在的区域。

### 长距离还会影响反向传播

对一个标量 RNN，设 $a_t=w_xx_t+w_hh_{t-1}+b$，那么：

$$
\frac{\partial h_t}{\partial h_{t-1}}
=(1-\tanh^2(a_t))w_h
$$

跨越多个步骤时，链式法则要求把这些局部导数相乘。如果每一步的乘积因子约为 0.5，经过 10 步只剩 $0.5^{10}\approx0.001$。反过来，持续放大的因子也可能造成梯度爆炸。

向量情况是雅可比矩阵连乘，不能直接等同于固定乘某个标量；这个例子解释的是“多次连乘为什么可能不稳定”。前向信息衰减与反向梯度衰减相关，但不能把两者当成同一个量。

## 4. LSTM：分别控制保留、写入和当前输出

当人物与预测位置相隔很多步时，RNN 要反复变换同一份状态。早期差异可能变弱，反向传播也可能遇到梯度消失或爆炸。

### 先从一个容易保留旧值的更新式出发

假设专门维护一个记忆向量 `c`，先尝试：

```python
c_new = c_old + new_content
```

没有新内容时，旧值能直接传下去，但没有专门的机制决定哪些旧内容该丢弃。于是给旧记忆乘一个保留系数：

```python
c_new = f * c_old + new_content
```

旧值为 10 时，`f=1` 保留 10，`f=0.5` 保留 5，`f=0` 清空。这个逐分量的保留控制就是遗忘门。

再考虑中间那些无关字符：即使旧值保留了，新内容不停写入也可能干扰记忆。因此还需要输入门：

```python
c_new = f * c_old + i * g
```

`g` 是候选内容，`i` 决定写入比例。例如 `c_old=0.8、f=1、i=0.5、g=-0.4`，更新后为 `0.6`。

门不能只是训练后固定的一组比例，否则不管读到人物还是填充字符，每一步都会按相同方式保留。它必须根据当前输入和前文计算，所以由线性层生成分数，再用 sigmoid 映射到 0～1。

LSTM 增加细胞状态 $c$，用门控制记忆更新：

$$
\begin{aligned}
f_t &= \sigma(W_fx_t+U_fh_{t-1}+b_f)\\
i_t &= \sigma(W_ix_t+U_ih_{t-1}+b_i)\\
g_t &= \tanh(W_gx_t+U_gh_{t-1}+b_g)\\
o_t &= \sigma(W_ox_t+U_oh_{t-1}+b_o)\\
c_t &= f_t\odot c_{t-1}+i_t\odot g_t\\
h_t &= o_t\odot\tanh(c_t)
\end{aligned}
$$

| 变量 | 作用 |
| --- | --- |
| $f$ | 旧记忆保留多少 |
| $i$ | 候选内容写入多少 |
| $g$ | 准备写入的内容 |
| $o$ | 当前向隐藏状态提供多少记忆 |

这些门不是固定的保留比例。权重是参数，门值则由当前输入和旧隐藏状态动态计算。模型可以针对不同上下文产生不同决定。

对某个分量，如果 $f\approx1$、$i\approx0$，旧记忆可以基本保持不变。如果 $o\approx0$，这部分记忆暂时不出现在 `h` 中，但 `c` 不会因此被清空。

因此可以把 `c` 理解为内部保存的信息，`h` 理解为当前对外提供的表示。不过“长期”和“短期”不是严格的时间划分：`c` 也可能快速更新，`h` 也可能包含很早的信息。

### 为什么需要 c 和 h 两个状态？

“当前需要输出的内容”和“以后还要用的内容”可能不同。例如读到“我今天早”时，预测下一个“上”需要处理局部表达，但人物信息最好继续保存，以便后面选择茶或水。

LSTM 用输出门控制当前可见的表示：

```python
h = o * torch.tanh(c)
```

如果某个 `c` 分量为 0.8，而对应 `o` 接近零，那么对应 `h` 接近零，`c` 仍然保留 0.8。改变当前输出表示，不必同时抹掉内部记忆。

代码中要注意先算完门，再更新状态：

```python
f = torch.sigmoid(forget_x(x) + forget_h(h))
i = torch.sigmoid(input_x(x) + input_h(h))
g = torch.tanh(candidate_x(x) + candidate_h(h))
o = torch.sigmoid(output_x(x) + output_h(h))
c = f * c + i * g
h = o * torch.tanh(c)
```

四项都使用旧 `h`。门、候选内容、`h`、`c` 的 shape 都是 `[B, H]`，上述乘法都是逐元素相乘。

“输出门”也不是“词表输出层”。输出门形成 `h`，之后仍要用 `Linear(H, N)` 产生各字符的分数。续写时要同时传递最后的 `(h, c)`；独立句子开始时，两者都从零开始。

### 有门不等于一定能记住

受控实验只训练两种映射：人物“我”对应茶，“他”对应水，中间插入若干个“啊”，只在最后“喝”的位置计算预测 loss。这样不会让大量容易预测的填充字符稀释错误。

在固定种子 42、Adam 学习率 0.01、300 轮的设置下：

| 中间字符数 | RNN 正确目标概率 | LSTM 正确目标概率 |
| --- | --- | --- |
| 2 | 约 99.98% | 约 99.99% |
| 8 | 约 99.96% | 约 99.95% |
| 20 | 约 50% | 约 50% |
| 50 | 约 50% | 约 50% |

这是开发过程中的单次观察，不是 RNN 或 LSTM 的固定记忆上限，也没有单凭失败就证实梯度消失。

把 LSTM 遗忘门偏置初始化为 1 后，20 个填充字符的目标概率升到约 99.94%，50 个时仍接近 50%。初始化影响了学习结果，但没有自动解决问题。即使每步保留 90%，连续 50 步也只剩约 0.5%；更接近 1 的门值才有利于长期保留。

## 5. Attention：预测时直接读取历史状态

既然信息逐步传递可能丢失，就把各位置状态保存下来，让当前预测直接读取它们：

```text
原来：当前 h → 预测
现在：当前 h + 从历史状态读取的信息 → 预测
```

先算相关程度，再用 softmax 分配权重，最后加权求和：

```python
scores = Q @ K.transpose(-2, -1)
weights = masked_scores.softmax(dim=-1)
context = weights @ V
```

这里 Q 用于查询，K 用于匹配，V 提供被读取的内容。最初可以直接使用 LSTM 状态，随后增加三个独立线性层：

```python
Q = query(states)
K = key(history)
V = value(history)
```

这让模型分别学习如何查询、如何被匹配、传递什么信息，而不必三者都使用同一种原始表示。

`context` 虽然由状态加权得到，却不能完整保留每个原状态。例如 `[1, 0]` 与 `[0, 1]` 各取一半，结果 `[0.5, 0.5]` 无法单独告诉预测层哪个是当前位置。因此早期版本把当前状态和 `context` 拼接后再预测，保留一条直接使用当前信息的路径。

### 点积、softmax、加权求和，各自在做什么？

用一个完全可手算的示意例子。设当前查询为 `[1, 0]`，两个 Key 分别为 `[2, 0]` 和 `[0, 1]`：

```text
分数1 = 1×2 + 0×0 = 2
分数2 = 1×0 + 0×1 = 0
```

softmax 后：

```text
权重1 = exp(2) / (exp(2)+exp(0)) ≈ 0.881
权重2 = exp(0) / (exp(2)+exp(0)) ≈ 0.119
```

如果两个 Value 是 `[10, 0]`、`[0, 20]`，读取结果就是：

```text
context = 0.881 × [10, 0] + 0.119 × [0, 20]
        ≈ [8.81, 2.38]
```

分数用于决定读取比例；Value 才是按这个比例搬过来的内容。Q/K/V 的线性层和上游表示一起训练，学习让这种读取有利于预测，而不是提前知道哪个词“重要”。

### states 和 context 到底有什么区别？

在 LSTM 加 Attention 的版本中：

```text
states 中的 h₁：读完“我”后的状态
states 中的 h₂：读完“我喝”后的状态
context₂：位置2按当前权重汇总历史状态得到的信息
```

`states` 保存逐位置计算结果，`context` 保存逐位置发起查询后的读取结果。两者 shape 可以相同，但内容和用途不同。

LSTM 版本里，一个位置的状态已经受前面多个字影响，因此关注这个位置不等于只读取那个单字。后来移除 LSTM 后，第一层输入状态的含义会改变，而 Attention 的读法不变。

### 为什么查询和内容需要不同的投影？

直接点积原始状态，只比较对应维度。例如 `[1, 0]` 与 `[0, 1]` 点积为零。但任务可能需要把前者的第一个特征与后者的第二个特征匹配。可训练投影能重新组合特征，使这类匹配成为可能。

K 负责“怎样被找到”，V 负责“找到后传递什么”。二者可以来自同一个原始状态，但没有必要使用同一套加工规则。不同线性层提供了这种自由度，不代表每个维度都会对应可命名的语义。

### 不能偷看答案

训练输入“我喝茶。”时，“喝”位置的目标是“茶”。如果它能读取后面的状态，就可能获得答案。

因此 softmax 前要把未来位置设为负无穷：

```python
scores = scores.masked_fill(future_mask, float("-inf"))
weights = scores.softmax(dim=-1)
```

负无穷对应的指数为零，所以权重为零。直接把分数设成零没有这个效果，因为 $e^0=1$。对角线保留：当前位置的输入已经可用。

以“我喝茶。”为例，一张分数表的行表示发起查询的位置，列表示被读取的位置：

```text
             我     喝     茶     。
我           保留   遮住   遮住   遮住
喝           保留   保留   遮住   遮住
茶           保留   保留   保留   遮住
。           保留   保留   保留   保留
```

代码中的上三角布尔矩阵正好表示这些未来位置。遮罩不是删除数据，而是在 softmax 之前让相应分数无法获得权重。这样既可以整段计算所有位置，又不改变“每个位置只能使用前缀”的训练条件。

### 从一组权重到多组权重

单头 Attention 让全部 Value 特征共用一组位置权重。多头把特征分组，让不同组各自计算权重。

当前模型将 32 维拆成 4 个头，每头 8 维：

```python
x = x.reshape(B, L, 4, 8).transpose(1, 2)
# [B, L, 32] -> [B, 4, L, 8]
```

拆的是每个位置的特征，不是把句子切成四段。每个头仍能读取所有允许的位置。

点积分数除以每头维度的平方根：

```python
scores = (Q @ K.transpose(-2, -1)) / (8 ** 0.5)
```

在各分量独立、零均值、单位方差的简化假设下，点积的方差随维度增长，标准差随平方根增长。缩放用于控制分数尺度，避免 softmax 过早变得极端，不保证每次实验都提高准确率。

各头结果先交换回 `[B, L, 4, 8]`，再合并成 `[B, L, 32]`，最后经过输出投影混合。不能省略交换维度就直接 reshape，否则可能混淆位置与头的数据顺序。

### 四个头的结果如何对应原来的位置？

可以把四维张量写成带名字的格子：

```text
拆头后 [B, 4, L, 8]：
头0：[位置0的8个数，位置1的8个数，……]
头1：[位置0的8个数，位置1的8个数，……]
……
```

合头时需要的是：

```text
位置0：[头0的8个数，头1的8个数，头2的8个数，头3的8个数]
位置1：[头0的8个数，头1的8个数，头2的8个数，头3的8个数]
```

因此先 `transpose(1, 2)`，再合并最后两个维度。转置在这里解决的是数据对应关系，不只是为了凑出一个目标 shape。

保持总维度 32 时，单纯把头数从 1 改成 4，并不会让 Q/K/V 线性层的参数量乘四：仍然是三组 `32 → 32` 投影。多头改变了输出特征的分组与注意力计算方式。本文另外加入的输出投影，则确实增加了一组可训练参数。

## 6. 去掉 LSTM：让 Attention 负责位置间的信息交流

有了 Attention，可以直接从字符表示生成 Q/K/V，不再逐字计算递归状态。但去掉 LSTM，也去掉了它通过顺序处理提供的表示。

因此给每个位置添加可训练的位置向量：

```python
states = token_embedding(input_ids) + position_embedding(positions)
```

同一个字在不同位置得到不同输入表示。因果遮罩规定可见范围，位置向量提供显式位置信息，两者作用不同。

这个变化还改变了 `states` 的含义：

- 在 LSTM 版本中，一个位置的状态已经受前文影响。
- 去掉 LSTM 后，第一层之前的状态只有字符与位置信息；通过 Attention 后才融合其他位置的信息。

训练时各位置的输入表示可以同时计算，Attention 也可以用矩阵运算处理整段序列。生成仍然逐 token 进行，因为后续输入取决于前一步生成结果。

### 从递归代码到一次查表

原来的输入处理是：

```python
states = []
for position in range(length):
    # 当前状态依赖上一步 h、c
    h, c = lstm_step(vectors[:, position], h, c)
    states.append(h)
```

新的处理是：

```python
positions = torch.arange(past_len, past_len + length, device=input_ids.device)
states = embedding(input_ids) + position_embedding(positions)
```

两个 Embedding 的最后一维都设为 32，才能逐元素相加。位置表第 0 行、第 1 行等也是可训练参数，而不是把整数位置简单加到向量每个元素上。

续写时，提示词有两个字，新字应该使用位置 2。即使这次调用只传一个 token，也不能重新使用位置 0。代码因此用缓存长度 `past_len` 确定起点。

位置表有 64 行，只意味着允许查询编号 0～63，不意味着这份短语料充分训练了所有位置，更不意味着模型能可靠泛化到 64 个字。

## 7. 残差、FFN、LayerNorm：形成一个 Transformer 块

继续叠层需要固定宽度的表示。模型把原来的拼接改成残差相加：

```python
x = states + attention_output
```

输出投影可以学习把读取到的信息转换成适合相加的更新；如果更新接近零，原表示仍然直接传下去。

Attention 负责读取其他位置，FFN 则分别加工各位置内部的特征：

```python
ffn = nn.Sequential(
    nn.Linear(32, 64),
    nn.ReLU(),
    nn.Linear(64, 32),
)
x = x + ffn(x)
```

所有位置共享这组 FFN 参数，但独立计算。Attention 本身已有 softmax 非线性；FFN 增加的是逐位置、跨特征的非线性加工能力。

残差反复相加后，数值尺度可能变化。当前采用 Pre-LN，在子层前做 LayerNorm：

```python
x = x + attention(attention_norm(x))
x = x + ffn(ffn_norm(x))
```

这段是结构示意，实际 Attention 还要接收因果遮罩及缓存。`LayerNorm(32)` 对每个位置自己的 32 个数做归一化，再通过可训练的缩放和偏移调整，不把不同句子、不同位置混起来。

两组计算构成一个 Transformer 块。创建两个独立的块：

```python
self.layers = nn.ModuleList([
    TransformerBlock() for _ in range(2)
])
```

第二层接收第一层融合过上下文的输出，并拥有自己的参数。最后增加 `final_norm`，再用线性层映射到词表分数。

```text
字符与位置向量
→ Transformer 块0
→ Transformer 块1
→ 最终 LayerNorm
→ 词表分数
```

这已经是一个简化的 GPT 风格模型。增加组件不等于验证结果必然变好：开发过程中，一些版本的验证续写从 4/4 降到 1/4 或 2/4。结构变化、初始化和小数据都可能影响结果，不能把单次变化当成因果结论。

### 为什么相加还能保留信息？

残差不是无损拼接，两个向量相加也可能丢失区分信息。它提供的是一条可学习更新之外的直接通路：

```text
x = [1.0, 2.0, -1.0]
更新 = [0.2, 0.0, -0.3]
新表示 = [1.2, 2.0, -1.3]
```

模型可以学习小幅修改已有表示，而不必每个子层都从头重建。对 `y=x+F(x)`，梯度中有直接来自 `x` 的那条分支，以及经过 `F` 的分支。这有助于优化深层网络，但不意味着永远不会出现梯度或信息问题。

### FFN 为什么不混合位置？

对于 `[B, L, 32]`，`Linear(32, 64)` 作用于最后一维。每个位置都分别执行同一个小网络：

```text
位置0的32维 → Linear → ReLU → Linear → 位置0的新32维
位置1的32维 → Linear → ReLU → Linear → 位置1的新32维
```

前一个 Attention 已经把上下文带进各位置，FFN 再加工这些特征。第一层扩到 64 维提供更多中间组合，ReLU 加入非线性，第二层回到 32 维以便残差相加。64 是本实验的选择，不是所有 Transformer 必须使用的大小。

### LayerNorm 的计算范围与位置

对某一位置的向量 $x$，先计算它自己的特征均值与方差：

$$
\mu=\frac1D\sum_{j=1}^{D}x_j,\qquad
\sigma^2=\frac1D\sum_{j=1}^{D}(x_j-\mu)^2
$$

再计算：

$$
y_j=\gamma_j\frac{x_j-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_j
$$

例如 `[1,2,3,4]` 减去均值 2.5 后得到 `[-1.5,-0.5,0.5,1.5]`，再除以相应标准差。可训练的 $\gamma$ 与 $\beta$ 让模型调整尺度和偏移，最终输出不必固定为均值零、方差一。

Pre-LN 只归一化子层输入，残差主路径保留原表示。最后一层的残差输出尚未经过下一层的输入归一化，所以本文在预测层前再加一个 `final_norm`。

### 叠层不是重复调用同一套权重

下面的写法每次都创建一个新对象：

```python
self.layers = nn.ModuleList([TransformerBlock() for _ in range(2)])
```

循环执行时：

```python
for layer in self.layers:
    states, cache = layer(states, cache_for_this_layer)
```

第二层的输入是第一层输出；第二层的 Q/K/V、FFN、归一化参数也独立。第一层可能先读到人物，第二层就有机会基于已经带有人物信息的表示继续处理，但不能未经分析就给每一层指定固定的语义分工。

## 8. 训练：一句话读一次，每个位置预测下一个字

最直观的训练数据是把所有前缀分别列出来：

```text
我       → 喝
我喝     → 茶
我喝茶   → 。
我喝茶。 → <eos>
```

这会反复计算相同前缀。因果模型可以一次输入完整句子，在每个位置产生相同目标的预测：

```text
inputs：[我, 喝, 茶, 。]
labels：[喝, 茶, 。, <eos>]
```

对于不同长度的句子，在右侧补齐：

```text
inputs：我 喝 茶 。     <pad> <pad>
labels：喝 茶 。 <eos>  -100  -100
```

`<pad>` 是合法的输入编号，要进入 Embedding；`-100` 是目标中的忽略标记，不是词表编号，也不是“第 −100 个位置”。

```python
loss = F.cross_entropy(
    logits.reshape(-1, logits.shape[-1]),  # [B*L, N]
    labels.reshape(-1),                  # [B*L]
    ignore_index=-100,
    reduction="mean",
)
```

平均的分母只包含有效目标。长度为 4 和 6 的两句话，应除以 10，而不是补齐后的 12；也不应在希望每个 token 等权时，先各句平均再平均，否则短句中每个 token 权重更大。

当前只做右侧补齐。真实位置无法通过因果 Attention 读取其后的 pad，pad 位置自己的 loss 又被忽略，因此有效预测不受补齐影响。这个理由不自动适用于左侧补齐、双向 Attention 或复用补齐后的缓存。

训练循环仍然是：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

所有组件一起受同一个预测目标训练，不需要分别给 Embedding、Attention 和 FFN 设计答案。

### 训练调用的执行顺序

训练入口是：

```python
logits, _ = model(inputs)
```

没有缓存，位置从零开始，所有句子在各自 batch 行内独立计算。一次前向会依次完成：

1. 查字符表、位置表，得到 `[B, L, 32]`。
2. 第 0 层在因果范围内读取信息，再做 FFN。
3. 第 1 层继续处理第 0 层输出。
4. 最终归一化与预测层得到 `[B, L, N]`。
5. 与 `[B, L]` 的 labels 对齐，忽略补齐目标。

以 `B=1、L=4` 为例，reshape 只是把 `[1,4,N]` 改为 `[4,N]`。四行仍分别对应四个位置，没有再次堆叠，也没有混合其分数。

输入中的“茶”是真实语料的一部分，即使“喝”位置预测错了，后一个位置训练时仍然读真实的“茶”。这种使用真实前缀的训练方式，使所有位置可以在同一次前向中参与目标。生成阶段则必须读模型自己选出的字。

### loss 怎么知道该更新哪些参数？

PyTorch 在前向计算时记录运算依赖。预测分数来自最终线性层，线性层输入来自第二层，第二层又依赖第一层和 Embedding。`loss.backward()` 沿这些依赖应用链式法则，把贡献累加到各参数的 `.grad`。

并不是 loss 通过字符编号主动寻找“用了哪些层”；计算图已经记录了这条路径。没有参与当前有效目标计算的分支不会凭空获得来自该目标的梯度，参数在多个位置被使用时则收到各路径梯度的累加。

这也解释了为什么一句话读一次仍然能训练所有位置：共享的早期计算可以同时影响多个预测，反向传播会自动汇总这些影响。

## 9. 生成：从历史表示缓存到真正的 KV Cache

生成“我喝茶。”的流程是：

```text
读“我喝” → 选出“茶”
读新字“茶” → 选出“。”
读新字“。” → 选出 <eos>，停止
```

第一次处理提示词后，后续每次只处理新 token。仅保存历史输入表示还不够：如果每次都对全部历史重新执行 `key(history)` 和 `value(history)`，旧投影仍然重复计算。

真正的 KV Cache 保存投影后的结果：

```python
Q = split_heads(query(normalized_states))
K = split_heads(key(normalized_states))
V = split_heads(value(normalized_states))

if cache is not None:
    old_K, old_V = cache
    K = torch.cat([old_K, K], dim=2)
    V = torch.cat([old_V, V], dim=2)
```

逐字续写时：

| 张量 | Shape |
| --- | --- |
| 新 Q | `[B, 4, 1, 8]` |
| 拼接后的 K、V | `[B, 4, P+1, 8]` |
| 分数与权重 | `[B, 4, 1, P+1]` |
| 合头后的 context | `[B, 1, 32]` |

新 Q 仍需和全部历史 K 比较，并对 V 加权求和。缓存省掉旧位置的投影等重复计算，不是把每一步 Attention 变成与历史长度无关的工作。

每层输入及权重不同，所以两层分别保存自己的 `(K, V)`。新字的位置编号从缓存长度开始；一次输入多个新字时，因果遮罩也要按旧长度偏移。代码使用 `diagonal=past_len + 1`。

缓存只在参数不变的同一次生成中复用，不能跨优化器更新沿用。当前实现使用简单的 `torch.cat` 追加，适合教学，不是为高吞吐服务设计的缓存分配方案。

### 沿 complete 走一遍，而不是只看缓存公式

生成函数首先读完整个提示词：

```python
logits, cache = model(make_context("我喝", token_to_id))
```

这次输出 `[1,2,N]`，两个位置各有一组分数。下一步需要的是“我喝”后面的字，所以只取最后位置：

```python
next_id = logits[0, -1].argmax().item()
```

假设选中“茶”，把它拼到字符串里，并不代表缓存已经读到了“茶”。此时缓存仍只包含前两个位置。必须再调用：

```python
logits, cache = model(torch.tensor([[next_id]]), cache)
```

模型用位置编号 2 加工“茶”，在每层生成新 K/V，并追加到相应层的缓存。输出现在为 `[1,1,N]`，对应“我喝茶”后面的字符。

然后生成“。”，再读入“。”，最后如果选出结束标记就停止；结束标记不拼进返回的文字。生成函数用 `torch.no_grad()`，不记录供反向传播使用的计算图，也没有参数更新。

### 为什么不缓存 Q？

旧位置的查询已经产生过输出。当前任务只需要为新位置算输出，不需要重新回答“我”位置当时会关注什么。旧位置仍然需要被新查询读取，因此保存 K、V；新位置的 Q 当次计算即可。

### 缓存后的遮罩为什么要偏移？

假设已有三个旧位置，一次再输入两个新位置。分数矩阵是两行、五列：

```text
             旧0  旧1  旧2  新3  新4
新3查询       ✓    ✓    ✓    ✓    ×
新4查询       ✓    ✓    ✓    ✓    ✓
```

这时不能套用从第 1 列开始遮的普通上三角。新查询在完整序列里的位置有偏移，所以用：

```python
future_mask = torch.triu(
    torch.ones(new_len, total_len, dtype=torch.bool),
    diagonal=past_len + 1,
)
```

训练时旧长度为零，自动退化为普通因果遮罩；逐字续写时没有尚未读到的新位置需要遮住。

### 缓存要付出什么代价？

每层的 K 和 V 都随历史长度增长。对于两层、四头、每头 8 维、batch 为 1、历史长度 64、float32 的本模型，缓存元素占用为：

```text
2层 × 2份(K和V) × 1个样本 × 4头 × 64位置 × 8维 × 4字节
= 32768字节，约32 KiB
```

这不包含参数、其他张量或内存分配开销。模型规模和序列长度扩大后，缓存的内存成本也会扩大。

本文检查过一次整段计算、逐字复用和分段复用的输出分数，差异约在浮点舍入量级；修改后缀不会改变前面位置的分数。这两类检查分别验证缓存衔接和因果性，而不是验证模型泛化能力。

## 10. 验证：能复现训练句子，不等于能处理新组合

最终训练语料有 12 句，时间表达为“无时间词”“今天”“早上”，分别搭配人物“我／他”和动作“喝／吃”。约定“我”对应茶、苹果，“他”对应水、香蕉。

验证保留“今天早上”的四种组合，从随机参数重新训练，确保这些组合没有参与参数更新。它们用于开发期间检查结果，不能再称为一次性最终测试集。

最终脚本在本次环境中得到：

```text
训练 loss：约 0.3076
训练句子完整续写匹配：12/12
验证组合完整续写匹配：4/4
```

续写检查给出的是截至动作的前缀，例如“我今天喝”，再检查宾语、句号和结束。这不是从空文本生成整句的正确率。

### 为什么答对了，loss 还不为零？

训练中同时有“我今天喝茶”和“我今天吃苹果”。只看到“我今天”时，下一个字既可能是“喝”，也可能是“吃”。当前模型给两者各约 50%，这是合理的不确定性。

对概率 0.5 的正确答案，交叉熵仍为：

$$
-\log(0.5)\approx0.693
$$

模型不可能同时给两个不同答案都分配 100% 的概率。完整训练 loss 平均了这些有分支的位置与其他更确定的位置，因此不会因为某些续写全部正确就自动变为零。

四条验证样本只能说明这些组合的结果，不能证明广泛泛化。结构优化也应结合多次运行、更丰富的独立数据和明确指标评价。

## 11. 为什么这个模型叫 Decoder-only？

“编码输入”这个动作，不等于拥有一个独立的 Transformer Encoder 模块。所有这些模型都可能把 token 转成向量并加工表示。

| 架构 | 信息流动 | 例子 |
| --- | --- | --- |
| Encoder-only | 每个位置读取双向上下文，得到输入表示 | BERT |
| Encoder–Decoder | Encoder 处理源序列，Decoder 读取源表示和目标前缀 | 原始 Transformer 翻译模型 |
| Decoder-only | 只沿一条因果路径，根据自己的前文生成 | GPT、本文模型 |

翻译模型中，Decoder 的 Cross-Attention 用自身表示生成 Q，用 Encoder 输出生成 K、V。本文没有独立源序列的 Encoder，也没有这条 Cross-Attention，只包含因果 Self-Attention，因此是 Decoder-only。

BERT 的遮盖语言建模通过双向上下文恢复被遮住的 token；当前模型则在各位置预测下一个 token。二者不仅可见范围不同，训练目标也不同。

### 从翻译例子区分 Encoder 和 Decoder

考虑把 `I drink tea.` 翻译成“我喝茶。”：

```text
英文 → Encoder → 英文的上下文表示
                         ↓
中文前缀 ────────────→ Decoder → 下一个中文字
```

Encoder 可以让英文中的每个位置读取整段英文，得到适合后续使用的表示。Decoder 一方面通过因果 Self-Attention 读取已经给出的中文前缀，另一方面通过 Cross-Attention 读取英文表示。

因此原始 Encoder–Decoder 结构中的 Decoder 块通常包含两种 Attention：

```text
因果 Self-Attention：中文前缀内部读取
Cross-Attention：读取 Encoder 的英文表示
FFN：加工各位置特征
```

GPT 风格的 Decoder-only 不需要独立源序列的 Encoder，也就没有这条 Cross-Attention。它不是“完全不编码”，也不是将翻译 Decoder 原样搬来，而是直接用因果块处理自己的前文并生成。

### 双向读取为什么不会总是偷看答案？

是否泄漏取决于任务。在 next-token 训练中，让位置看到它正在预测的下一个真实 token 是泄漏；在遮盖语言建模中，目标位置的内容被遮住或替换，使用其他可见位置的左右上下文正是任务设定。

所以不能脱离目标说“右边永远不能看”。本文的因果限制来自自回归续写任务，BERT 的双向可见性来自不同的建模方式。当前阶段需要掌握的是可见范围、信息来源和训练目标的对应关系，而不是把 Encoder 和 Decoder 当作互为逆运算的两个函数。

## 总结：每个组件解决了什么问题？

| 组件或改动 | 解决的问题 |
| --- | --- |
| Embedding | 让离散编号对应可训练的向量 |
| 多字窗口 | 把判断所需的邻近信息送进模型 |
| RNN / LSTM | 逐步携带前文，学习控制记忆更新 |
| Attention | 直接读取历史位置的信息 |
| Q/K/V 投影 | 分别学习查询、匹配与内容表示 |
| 多头 | 让特征分组拥有不同的注意力权重 |
| 位置向量 | 显式提供位置，不依赖递归处理 |
| 残差与 FFN | 保留已有表示，进一步加工各位置特征 |
| LayerNorm | 整理送入子层及预测层的特征尺度 |
| 因果遮罩与 labels | 对齐 next-token 目标，防止偷看未来 |
| KV Cache | 在生成时复用各层已算好的 K、V |
| 留出验证 | 区分拟合训练例子与处理新组合 |

完整流程最终回到一个清晰的任务：把前文变成表示，为下一个 token 打分，通过 loss 学习参数，再反复使用这个预测能力生成文本。模型结构负责提供计算能力，数据与评估决定这些能力是否真的被学到。
