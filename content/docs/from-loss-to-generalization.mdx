一个机器学习训练循环通常只有几步：计算预测、计算损失、反向传播、更新参数。但训练代码能够运行，并不代表训练目标、参数更新和评价方式都正确。理解这个过程，需要先回答几个问题：

- 模型到底在学习什么？
- `loss.backward()` 和参数更新分别做了什么？
- 为什么训练集 Loss 很低，模型仍然可能很差？
- Sigmoid、Softmax、BCE、Cross Entropy 分别负责什么？
- Accuracy 已经很高了，为什么还需要 Precision、Recall 和 F1？
- 神经网络里的矩阵乘法和链式法则，到底怎样接到训练过程上？

本文以线性模型和二分类任务为例，说明这些步骤如何连接起来。文中的 Loss 指损失函数的计算结果，用于衡量预测与目标的差异；训练负责降低训练目标，验证和测试负责检查模型在未参与参数更新的数据上的表现。完整流程如下：

```text
数据
  ↓
模型根据参数产生预测
  ↓
Loss 衡量预测有多差
  ↓
backward 计算 Loss 对参数的梯度
  ↓
参数沿梯度反方向更新
  ↓
在验证集上选择模型
  ↓
最后在测试集上评价泛化能力
```

## 符号约定

本文用**普通斜体表示标量**（如 $x,w,b$），用**粗体小写表示向量**（如 $\mathbf{x},\mathbf{w}$），用**粗体大写表示矩阵**（如 $\mathbf{X},\mathbf{W}$）。$\boldsymbol{\theta}$ 表示将模型参数展平后组成的参数向量。

$\ell$ 表示单个样本的损失，$L$ 表示一批样本的平均损失。代码中的 `X`、`w` 和 `loss` 是对应变量名；`[B, D]` 表示 Tensor 的 shape，其中 $B$ 是批大小，$D$ 是特征数。数学中的向量默认按列向量理解，数据矩阵每一行存放一个样本的转置。

## 训练如何改变模型参数

先看最简单的线性模型：

$$
\hat{y}=wx+b
$$

这里：

- `x` 是输入；
- `y_hat` 是模型预测；
- `w` 和 `b` 是参数。

在这个模型中，函数形式已经确定，训练改变的是 `w` 和 `b` 的数值。每次更新都依据样本上的预测误差，调整下一次计算所使用的参数。

假设数据背后的规律是：

$$
y=2x+1
$$

模型一开始可能是：

$$
\hat{y}=0.3x-0.5
$$

它现在显然拟合得不好。训练要做的事情，就是根据样本不断调整参数，最后得到一组接近正确规律的 `w` 和 `b`。

这里需要区分模型结构和模型参数：`w * x + b` 定义了模型能表达哪类关系，`w` 和 `b` 决定这类关系中的具体一条直线。训练可以调整参数，但不能把这个模型自动变成任意曲线。

当然，真实神经网络里的参数不再只有两个，而可能有几十亿甚至更多。但无论模型多复杂，训练的基本问题仍然一样：

**寻找怎样的参数，才能降低预测误差？**

---

## Loss 是参数好坏的评分函数

有了预测以后，还需要一种方法判断当前参数到底好不好，这就是 Loss。

以回归问题中的均方误差 MSE 为例：

$$
L_{\mathrm{MSE}}=\frac{1}{B}\sum_{i=1}^{B}(\hat{y}_i-y_i)^2
$$

如果预测接近真实值，Loss 就小；如果差得很远，Loss 就大。

因此可以把训练理解成一个优化问题：

$$
\boldsymbol{\theta}^{*}\in\operatorname*{arg\,min}_{\boldsymbol{\theta}}L(\boldsymbol{\theta})
$$

这里 $\operatorname*{arg\,min}$ 表示使目标最小的参数取值。实际训练通常通过迭代更新寻找近似解。

模型、参数和 Loss 的关系可以概括成：

**参数 → 预测 → Loss**：参数决定预测，预测与目标的差异决定损失。

但 Loss 只告诉我们“现在有多差”，没有直接告诉我们参数下一步应该怎么改。这个方向由梯度提供。

---

## 梯度告诉参数往哪里变化

梯度可以理解成：

> **梯度**是 Loss 对所有参数的偏导数组成的向量。

$$
\nabla_{\boldsymbol{\theta}}L=\begin{bmatrix}\frac{\partial L}{\partial\theta_1}\\\vdots\\\frac{\partial L}{\partial\theta_P}\end{bmatrix}\in\mathbb{R}^{P}
$$

其中 $P$ 为参数总数。

如果只有一个参数 `w`，那么只需要看：

$$
\frac{\partial L}{\partial w}
$$

如果这个导数是正数，说明在当前位置增大 `w` 会让 Loss 增大，因此应该减小 `w`。

如果导数是负数，说明增大 `w` 会让 Loss 减小，因此应该增大 `w`。

这两种情况统一写成梯度下降：

$$
\boldsymbol{\theta}_{t+1}=\boldsymbol{\theta}_t-\eta\nabla_{\boldsymbol{\theta}}L(\boldsymbol{\theta}_t)
$$

其中 $t$ 是更新步数，$\eta$ 是**学习率**。为什么需要它？

因为梯度只适合告诉我们局部方向，不适合直接充当参数的变化量。假设当前 `w=1`、梯度是 `-35`，如果直接减去梯度：

$$
w_{\mathrm{new}}=1-(-35)=36
$$

这一步可能跨过最低点很远，甚至让 Loss 爆炸。学习率就是每一步的步长：

- 学习率太大，可能来回震荡甚至发散；
- 学习率太小，下降稳定但训练很慢；
- 在平滑的局部极小点附近，梯度通常趋近于零；但梯度很小本身不能证明模型效果已经足够好。

在 PyTorch 中，计算梯度和更新参数是两个不同动作：

```python
loss.backward()  # 只计算梯度，把结果写入 parameter.grad

with torch.no_grad():
    parameter -= learning_rate * parameter.grad
```

一个很常见的误解是：

> **误区：调用 `loss.backward()` 就完成了参数更新。**

**`backward()` 负责计算梯度，更新操作才会改变参数。**

## Batch GD、SGD 和 Mini-batch SGD

它们的区别，不是 Loss 公式不同，而是每次用多少数据估计梯度。

### Batch Gradient Descent

每次使用整个训练集计算一次梯度：

**整个训练集 → 计算梯度 → 更新一次参数。**

梯度稳定，但数据量大时一次更新很慢。

### Stochastic Gradient Descent

严格意义上的 SGD 每次只使用一个样本：

**一个样本 → 计算梯度 → 更新一次参数。**

更新频繁，但梯度噪声很大。

### Mini-batch SGD

实际深度学习中最常见的是 Mini-batch：

**一小批样本 → 计算平均梯度 → 更新一次参数。**

它在计算效率和梯度稳定性之间取得平衡，也适合 GPU 的并行计算。

如果训练集有 10 个样本，batch size 是 4，那么一个 epoch 会分成：

```text
4 + 4 + 2
```

因此一个 epoch 更新 3 次参数，而不是 10 次，也不是 1 次。

## Train、Validation 和 Test 分别负责什么

把全部数据都拿来训练，会产生一个严重问题：我们不知道模型究竟学会了规律，还是只记住了原题。

所以通常把数据分成三部分：

| 数据集 | 职责 | 是否用于参数更新 |
| --- | --- | --- |
| **训练集（Train）** | 计算损失与梯度 | 是 |
| **验证集（Validation）** | 选择超参数和训练轮次 | 否，但影响模型选择 |
| **测试集（Test）** | 评价最终选定模型 | 否 |

可以把三者类比成：

**训练集是练习题，验证集是模拟考试，测试集是最终考试。**

验证集虽然不参与 `backward()`，却会间接影响训练决策。比如我们根据 `val_loss` 选择 epoch、学习率、模型大小或正则化强度，那么验证集实际上已经参与了模型选择。

如果反复根据验证集结果修改方案，最终也可能对验证集过拟合。因此测试集必须尽量保持封闭，只在所有决策完成之后使用。

## Supervised 和 Unsupervised 的根本区别

监督学习的数据包含输入和目标：

$$
(\mathbf{x}_i,y_i)
$$

同一个输入 `x`，如果标签 `y` 不同，Loss 和梯度也会不同，参数会被推向不同方向。标签实际在告诉模型：

**对这个输入，预测应该接近哪个目标。**

无监督学习没有人工标签 `y`，算法需要从输入本身寻找结构。例如聚类会尝试让同一组内的样本更接近、不同组之间更远。

但聚类中的类别数量通常不是算法天然知道的。像 K-Means 中的 `K` 往往需要人工指定，再结合业务含义、轮廓系数或肘部法等方法判断是否合理。

这也说明：

> 算法可以优化一个明确目标，但“应该分成几类”经常仍然是建模选择，而不是数据自动给出的唯一答案。

## Underfitting、Overfitting 和 Regularization

### 欠拟合

模型能力不足，连训练数据中的规律都没有学好：

**常见表现：训练损失和验证损失都较高。**

### 过拟合

模型把训练数据学得过于具体，甚至记住了噪声：

**常见表现：训练损失继续下降，验证损失却开始升高。**

因此不能只看训练 Loss。训练集告诉我们“原题做得怎么样”，验证集才更能反映“新题做得怎么样”。

一个常用办法是 L2 Regularization：

$$
J(\boldsymbol{\theta})=L_{\mathrm{data}}(\boldsymbol{\theta})+\lambda\lVert\boldsymbol{\theta}\rVert_2^2
$$

其中 $\lambda\geq 0$ 控制惩罚强度，$\lVert\boldsymbol{\theta}\rVert_2^2=\sum_j\theta_j^2$。**L2 正则化**限制参数幅度，但能否改善泛化仍需由验证结果判断。

但是 `lambda` 不是越大越好：

- 太小，约束不足，仍可能过拟合；
- 太大，模型不敢使用足够大的参数，会发生欠拟合。

正则化的本质不是让参数越小越好，而是在拟合数据与控制复杂度之间做权衡。

## 回归和分类的输出有什么不同

回归通常预测连续数值：

例如房价、温度、时长和收入。

模型可以直接输出一个实数，再使用 MSE 等 Loss。

分类预测的是离散类别：

例如判断交易是否欺诈、图片属于哪类物体，或一句话表达哪种意图。

分类模型通常先输出 logits。Logit 不是概率，它只是模型对各类别给出的原始分数。

二分类常见输出 shape：

```text
logits: [batch_size]
```

多分类常见输出 shape：

```text
logits: [batch_size, num_classes]
```

## 二分类：Sigmoid 和 BCE

Sigmoid 把任意实数 logit 转换到 0 和 1 之间：

$$
\sigma(z)=\frac{1}{1+e^{-z}}
$$

它有几个直观性质：

$$
\begin{aligned}z>0&\Rightarrow\sigma(z)>\tfrac12\\z=0&\Rightarrow\sigma(z)=\tfrac12\\z<0&\Rightarrow\sigma(z)<\tfrac12\end{aligned}
$$

因此默认阈值为 0.5 时：

$$
\sigma(z)\geq 0.5
$$

和下面完全等价：

$$
z\geq 0
$$

二分类交叉熵 BCE 是：

$$
\ell_{\mathrm{BCE}}=-\bigl[y\log p+(1-y)\log(1-p)\bigr],\qquad p=\sigma(z)
$$

当 `y=1` 时，只剩：

$$
\ell=-\log p
$$

当 `y=0` 时，只剩：

$$
\ell=-\log(1-p)
$$

所以 BCE 的行为是：

| 预测情况 | 正确类别的概率 | 损失表现 |
| --- | --- | --- |
| 正确且自信 | 接近 1 | 很小 |
| 接近分类阈值 | 接近 0.5 | 错误和正确两侧的损失都不会很小 |
| 错误且自信 | 接近 0 | 很大 |

实际训练时应该直接传入 logits：

```python
loss = F.binary_cross_entropy_with_logits(logits, labels)
```

不要先手动调用 Sigmoid。融合后的实现可以避免概率趋近 0 或 1 时出现数值精度问题。

对于单个样本，BCE 对 logit 的梯度可以简化为：

$$
\frac{\partial\ell}{\partial z}=p-y
$$

如果真实标签是 1，梯度小于等于 0，梯度下降会提高 logit；如果真实标签是 0，梯度大于等于 0，梯度下降会降低 logit。

## 多分类：Softmax 和 Cross Entropy

多分类中，一个样本会得到多个 logits：

$$
\mathbf{z}=\begin{bmatrix}2\\1\\0\end{bmatrix}
$$

Softmax 将它们转换成总和为 1 的概率：

$$
p_k=\frac{e^{z_k}}{\sum_{j=1}^{C}e^{z_j}},\qquad\mathbf{p}=\operatorname{softmax}(\mathbf{z})\approx\begin{bmatrix}0.665\\0.245\\0.090\end{bmatrix}
$$

Softmax 更关心 logits 之间的相对差距，而不是绝对大小。因此：

$$
\operatorname{softmax}\!\left(\begin{bmatrix}2\\1\\0\end{bmatrix}\right)=\operatorname{softmax}\!\left(\begin{bmatrix}1002\\1001\\1000\end{bmatrix}\right)
$$

会得到相同的概率分布。因为所有指数项都多乘了同一个 `exp(1000)`，在分子和分母中可以约掉。

实际实现通常先减去每行最大值：

```python
shifted_logits = logits - logits.max(dim=1, keepdim=True).values
probabilities = torch.exp(shifted_logits)
probabilities /= probabilities.sum(dim=1, keepdim=True)
```

`keepdim=True` 会把按行聚合后的 shape 保留为：

```text
[batch_size, 1]
```

这样每个样本的最大值或分母才能沿类别维度正确广播。

多分类交叉熵的完整形式是：

$$
\ell_{\mathrm{CE}}=-\sum_{c=1}^{C}y_c\log p_c
$$

这里 $C$ 是类别数，$\mathbf{y}$ 是 **one-hot 标签向量**。普通单标签分类中，只有真实类别的位置是 1，其他位置都是 0，所以最终只剩：

$$
\ell_{\mathrm{CE}}=-\log p_{c^*}
$$

其中 $c^*$ 是真实类别的索引。正确类别的概率越高，Loss 越小；正确类别的概率越低，Loss 越大。

PyTorch 中同样应该直接传 logits：

```python
loss = F.cross_entropy(logits, labels)
```

不要先手动 Softmax。`cross_entropy` 会使用数值稳定的方式合并 LogSoftmax 和负对数似然计算。

对于单个样本，它对第 `k` 个 logit 的梯度是：

$$
\frac{\partial\ell}{\partial z_k}=p_k-y_k
$$

例如：

$$
\nabla_{\mathbf{z}}\ell=\mathbf{p}-\mathbf{y}=\begin{bmatrix}0.7\\0.2\\0.1\end{bmatrix}-\begin{bmatrix}1\\0\\0\end{bmatrix}=\begin{bmatrix}-0.3\\0.2\\0.1\end{bmatrix}
$$

梯度下降会增大正确类别的 logit，同时压低两个错误类别的 logits。错误类别当前概率越高，受到的向下调整越强。

每个样本的这些梯度相加为 0：

$$
\sum_{k=1}^{C}(p_k-y_k)=1-1=0
$$

这与 Softmax 的平移不变性一致：同时给所有 logits 加上同一个常数，不会改变概率，也不会改变交叉熵。批量训练若取平均损失，上述每个样本的梯度还需除以 batch 大小。

## 为什么 Accuracy 不够

假设有 100 个样本：

其中 **95 个是负类，5 个是正类**。

如果模型把所有样本都预测为负类，它的 Accuracy 仍然有 95%。但如果正类代表疾病、欺诈或系统故障，这个模型一个目标都没有找出来。

二分类需要先统计混淆矩阵：

| 真实情况 | 模型预测 | 名称 | 含义 |
|---|---|---|---|
| 正类 | 正类 | TP | 正类预测正确 |
| 正类 | 负类 | FN | 正类被漏掉 |
| 负类 | 正类 | FP | 负类被误报 |
| 负类 | 负类 | TN | 负类预测正确 |

常用指标是：

$$
\begin{aligned}\mathrm{Accuracy}&=\frac{TP+TN}{TP+TN+FP+FN}\\[4pt]\mathrm{Precision}&=\frac{TP}{TP+FP}\\[4pt]\mathrm{Recall}&=\frac{TP}{TP+FN}\\[4pt]F_1&=\frac{2\,\mathrm{Precision}\,\mathrm{Recall}}{\mathrm{Precision}+\mathrm{Recall}}\end{aligned}
$$

可以这样记：

- **Precision（精确率）**：预测为正类的样本中，有多少确实是正类。
- **Recall（召回率）**：所有真实正类中，有多少被模型找出来。

降低二分类阈值，模型会预测出更多正类：

- Recall 通常会上升；
- Precision 通常会下降，但并非数学上必然下降；
- Accuracy 也不一定如何变化，要看新增的 TP 和 FP 谁更多。

严重疾病的初步筛查更怕漏掉患者，因此通常优先关注 Recall；误报代价特别高的系统则更关注 Precision。

## 向量、矩阵和批量计算

一个包含 3 个特征的样本可以写成：

```text
x: [3]
```

它是一维向量。一个 batch 中有 4 个样本时：

```text
X: [4, 3]
```

它是二维矩阵，表示 4 个样本、每个样本 3 个特征。

将四个样本按行堆叠，得到数据矩阵；每个样本仍使用同一个权重向量：

$$
\mathbf{X}=\begin{bmatrix}x_{11}&x_{12}&x_{13}\\x_{21}&x_{22}&x_{23}\\x_{31}&x_{32}&x_{33}\\x_{41}&x_{42}&x_{43}\end{bmatrix},\qquad
\mathbf{w}=\begin{bmatrix}w_1\\w_2\\w_3\end{bmatrix}
$$

$$
\hat{\mathbf{y}}=\mathbf{X}\mathbf{w}+b\mathbf{1}_4\in\mathbb{R}^{4}
$$

$\mathbf{1}_4$ 是全 1 向量，表示将标量偏置加到每个样本上。代码中的 shape 对应为：

```text
X:     [4, 3]
w:        [3]
X @ w: [4]
```

每个样本与 `w` 做一次点积，因此得到 4 个预测值。

多分类需要每个样本产生多个输出：

```text
X:      [32, 128]
W:      [128, 10]
b:           [10]
logits: [32, 10]
```

一般地，$\mathbf{X}\in\mathbb{R}^{B\times D}$、$\mathbf{W}\in\mathbb{R}^{D\times C}$、$\mathbf{b}\in\mathbb{R}^{C}$，批量 logits 为：

$$
\mathbf{Z}=\mathbf{X}\mathbf{W}+\mathbf{1}_B\mathbf{b}^{\mathsf T}\in\mathbb{R}^{B\times C}
$$

这里 $\mathbf{1}_B\mathbf{b}^{\mathsf T}$ 是偏置向量按行重复形成的矩阵，对应代码里的广播。

**矩阵乘法的维度规则**是：

```text
[m, n] @ [n, p] -> [m, p]
```

中间两个 `n` 必须相同，因为点积需要把 `n` 个元素一一配对、相乘并求和。

单个输出元素可以写成：

$$
Z_{ic}=\sum_{d=1}^{D}X_{id}W_{dc}+b_c
$$

后续学习 Linear Layer、Attention 和 Transformer 时，几乎所有 shape 推导都建立在这个规则上。

## 链式法则就是 backward 的数学基础

考虑一条计算链：

$$
w\longrightarrow z=xw\longrightarrow\ell=z^2
$$

`w` 先影响 `z`，`z` 再影响 Loss，因此：

$$
\frac{\partial\ell}{\partial w}=\frac{\partial\ell}{\partial z}\frac{\partial z}{\partial w}=2zx
$$

简单公式当然可以先展开再直接求导。但真实神经网络由大量算子组成，不可能人工展开成一个总公式。

Autograd 的做法是：

1. **前向记录计算图**：保存参与求导的运算关系。
2. **反向应用链式法则**：沿路径乘上局部导数，在分支汇合处累加贡献。
3. **累加参数梯度**：把结果写入叶子参数的 `.grad`。

例如同一个参数走两条路径：

```text
       ┌-> a = 2w -> loss_a = a² ┐
w -----|                          |-> loss = loss_a + loss_b
       └-> b = 3w -> loss_b = b² ┘
```

那么：

$$
\frac{\partial\ell}{\partial w}=\frac{\partial\ell_a}{\partial w}+\frac{\partial\ell_b}{\partial w}
$$

这也解释了为什么共享参数被多次使用时，梯度贡献必须汇总。

PyTorch 默认会累加 `.grad`，所以每次参数更新之后，还要在下一次 `backward()` 前清空旧梯度：

```python
w.grad.zero_()
b.grad.zero_()
```

使用优化器时，对应的是：

```python
optimizer.zero_grad()
```

## 最终实验：从零训练一个二分类模型

下面用二维线性可分数据说明训练、验证和测试如何衔接。模型接收两个特征，输出一个 logit，再用 BCE 计算训练损失。

数据由一条隐藏直线生成：

```python
torch.manual_seed(42)

features = torch.randn(120, 2)
teacher_w = torch.tensor([2.0, -3.0])
teacher_b = torch.tensor(0.5)

teacher_logits = features @ teacher_w + teacher_b
labels = (teacher_logits >= 0).to(torch.float32)
```

其中：

```text
features: [120, 2]
labels:   [120]
```

然后随机划分为：

```text
Train:      80
Validation: 20
Test:       20
```

模型参数从 0 开始：

```python
w = torch.zeros(2, requires_grad=True)
b = torch.zeros((), requires_grad=True)
```

这里 `b.shape == []`，表示它是一个**零维 Tensor（标量）**，包含一个数值，并不是空 Tensor。

核心训练循环没有使用高级训练框架：

```python
for epoch in range(1, num_epochs + 1):
    train_logits = X_train @ w + b
    train_loss = F.binary_cross_entropy_with_logits(
        train_logits,
        y_train,
    )

    train_loss.backward()

    with torch.no_grad():
        w -= learning_rate * w.grad
        b -= learning_rate * b.grad

    w.grad.zero_()
    b.grad.zero_()
```

每轮更新后，只用验证集做前向计算：

```python
with torch.no_grad():
    val_logits = X_val @ w + b
    val_loss = F.binary_cross_entropy_with_logits(
        val_logits,
        y_val,
    )
```

如果验证 Loss 更低，就复制并保存当前参数。等所有训练和参数选择结束后，才第一次使用测试集。

以下是示例训练 300 个 epoch 的结果。这里展示的是核心代码片段，未列出学习率和完整的数据划分代码，因此这些数字用于说明结果的解读方式，不作为逐项复现的基准：

| 指标 | 数值 |
| --- | --- |
| 初始训练 Loss | 0.6931 |
| 最终训练 Loss | 0.1873 |

学习到的权重与生成数据的权重分别为：

$$
\mathbf{w}_{\mathrm{learned}}=\begin{bmatrix}1.9186\\-2.6134\end{bmatrix},\qquad
\mathbf{w}_{\mathrm{teacher}}=\begin{bmatrix}2\\-3\end{bmatrix}
$$

参数不需要与生成数据的参数完全相同，仍然可以产生非常接近的分类边界。分类只关心样本落在边界哪一侧，而不是参数必须恢复成唯一数值。

最终测试结果：

| 指标 | 结果 |
| --- | --- |
| Accuracy | 0.950 |
| Precision | 1.000 |
| Recall | 0.857 |
| F1 | 0.923 |

混淆矩阵计数为 **TP=6、FN=1、FP=0、TN=13**。

也就是说，测试集上没有误报，但漏掉了一个正类。

这个实验很小，却完整走过了机器学习训练的核心链路：

```mermaid
flowchart LR
    A[准备并划分数据] --> B[矩阵乘法得到 logits]
    B --> C[BCE 计算 Loss]
    C --> D[backward 计算梯度]
    D --> E[梯度下降更新参数]
    E --> B
    E --> F[Validation 选择参数]
    F --> G[Test 最终评价]
```

## 从训练代码到评价结果，检查各环节的职责

阅读或实现一个训练程序时，可以用下面的对应关系检查每一步是否完整：

| 环节 | 核心职责 |
| --- | --- |
| **模型与参数** | 参数化输入到预测的映射 |
| **Loss 与梯度** | 衡量误差，并计算局部变化方向 |
| **参数更新** | 根据梯度和学习率修改参数 |
| **数据划分** | 分开参数学习、模型选择和最终评价 |
| **分类评价** | 根据任务同时观察损失、精确率和召回率等指标 |
| **矩阵与链式法则** | 分别支持批量前向计算和反向传播 |

排查训练问题时，先检查预测与标签的 shape、Loss 的输入形式和参数是否更新，再检查验证与测试是否独立。**训练 Loss 下降只说明训练目标得到了优化，不能替代对新样本的评价。**
