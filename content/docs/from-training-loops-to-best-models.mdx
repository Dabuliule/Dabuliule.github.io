上一篇[从线性层到神经网络：非线性、梯度与训练循环](/docs/from-linear-layers-to-neural-networks)，把一个小网络从矩阵计算一路写到了反向传播和参数更新。

接下来的问题变成了：当代码换成 `nn.Module`、DataLoader 和优化器以后，这些封装分别接管了什么？为什么同一个模型切换模式后行为会变？训练结束时，究竟应该留下哪一组参数？

这些机制分别管理不同的信息，不能相互替代：

| 组件 | 管理的内容 |
| --- | --- |
| 模型 | 参数、缓冲区和训练／评价模式 |
| 优化器 | 参数更新规则，以及动量等跨步骤统计 |
| DataLoader | 样本的读取顺序和 batch 组织 |
| 验证与检查点逻辑 | 模型选择指标、最佳轮次和保存的参数快照 |

本文依次说明这些职责，再将它们组合成“训练 → 验证 → 保存 → 恢复 → 测试”的流程。

## 符号约定

沿用前两篇的记法：**标量**写作 $x,\eta$，**向量**写作 $\mathbf{x},\boldsymbol{\theta}$，**矩阵**写作 $\mathbf{X},\mathbf{W}$。优化器公式中的 $\boldsymbol{\theta}$ 是展平后的参数向量，$\mathbf{g}_t$ 是第 $t$ 步梯度，$\eta$ 是学习率。

$\odot$ 表示**逐元素乘法**；向量的平方、平方根和除法也按元素计算。它们与矩阵乘法不同，下面会分别标明。

## Module 管理参数，但不会替模型定义计算

手写版本需要显式创建 `W1、b1、W2、b2`，并维护参数列表。`nn.Module` 通过参数注册统一管理这些对象，使优化器能够遍历模型参数。

```python
class TinyNetwork(nn.Module):
    def __init__(self):
        super().__init__()
        self.W = nn.Parameter(torch.randn(2, 3))
        self.b = nn.Parameter(torch.zeros(3))

    def forward(self, X):
        return X @ self.W + self.b
```

这里有两个容易混淆的概念：

- `requires_grad=True` 让 Tensor 的运算参与自动求导。
- 把 `nn.Parameter` 赋给 Module 属性，会将它注册为模型参数。

普通 Tensor 即使开启求导，也不会因为被放到 `self` 上就自动出现在 `model.parameters()` 中。它可能有梯度，却没有被交给优化器更新。

`forward` 则负责定义计算。日常使用 `model(X)` 调用模型，由 Module 的调用机制进入 `forward`，而不是把 Module 理解为自动生成网络计算的容器。

进一步换成 `nn.Linear`：

```python
self.layer1 = nn.Linear(2, 3)
```

它会创建并注册自己的权重和偏置。作为父模型的子模块，这些参数也会被父模型递归收集。

需要特别注意权重布局：

| 实现 | 权重 shape | 计算 |
| --- | --- | --- |
| 前文手写 | $\mathbf{W}\in\mathbb{R}^{2\times3}$ | `X @ W + b` |
| `nn.Linear(2, 3)` | $\mathbf{W}_{\mathrm{Linear}}\in\mathbb{R}^{3\times2}$ | `X @ weight.T + bias` |

输入仍是 `[B, 2]`，输出仍是 `[B, 3]`。核对两种实现时，应将手写的 `W.T` 复制到 `nn.Linear.weight`，并复制相同偏置。两者表达的是同一个仿射变换，区别在于权重的存储布局。

## 从一个 epoch 一次更新，到一个 batch 一次更新

Dataset 负责回答“有多少个样本”和“第 i 个样本是什么”，DataLoader 负责取样、组成 batch。

对于二维特征的回归数据：

```text
单个样本：特征 [2]，目标 [1]
组成 batch：特征 [B, 2]，目标 [B, 1]
```

5 个样本、`batch_size=2`、不丢弃最后一批，就会得到大小为 `2、2、1` 的三个 batch。完整读取一次数据是一个 epoch；每批更新一次时，一个 epoch 就有三次参数更新。

```python
for X_batch, y_batch in loader:
    optimizer.zero_grad()
    predictions = model(X_batch)
    loss = loss_function(predictions, y_batch)
    loss.backward()
    optimizer.step()
```

位置决定含义。如果只把 `step()` 移到循环外，而 `zero_grad()` 仍在每批开始执行，那么最后只会更新一次，而且使用最后一批的梯度，前两批梯度已经被清掉了。

记录指标也需要考虑 batch 大小。假设三个 batch 的平均 Loss 是 `L1、L2、L3`，按样本平均应该计算：

$$
L_{\mathrm{epoch}}=\frac{2L_1+2L_2+L_3}{5}
$$

直接除以三，会让最后那个样本获得过大的权重。

还有一个更细的区别：训练过程累计的 Loss 来自不断变化的参数；一个 epoch 结束后重新评价全部训练样本，使用的是同一组最终参数。这两个指标即使都计算正确，也不必相等。记录日志时应明确区分“训练过程中累计的 Loss”和“epoch 结束后的训练集 Loss”。

## 模型模式与梯度记录是两套机制

上一篇已经讨论过 `no_grad()`。引入 Module 后，需要再把它和模型模式分开：

| 操作 | 改变什么 |
| --- | --- |
| model.train() | 将模型及子模块切换为训练模式 |
| model.eval() | 将模型及子模块切换为评价模式 |
| torch.no_grad() | 关闭上下文内运算的梯度记录 |
| loss.backward() | 计算并累加参数梯度 |
| optimizer.step() | 根据梯度更新参数 |

**`eval()` 不会关闭计算图，`no_grad()` 不会关闭 Dropout。**对于只有 Linear 和 ReLU 的模型，模式切换暂时不改变前向规则；加入 Dropout 后，这个区别就能直接观察到。

训练时，**Dropout** 以概率 $p$ 将每个激活元素置零，保留下来的值除以 $1-p$。用掩码向量表示为：

$$
m_j\sim\operatorname{Bernoulli}(1-p),\qquad
\tilde{\mathbf{x}}=\frac{\mathbf{m}\odot\mathbf{x}}{1-p},\qquad 0\leq p<1
$$

这里 $m_j$ 是第 $j$ 个元素的掩码，取值为 0 或 1；$\mathbf{m}$ 只表示 Dropout 掩码，与后文 Adam 的历史统计无关。例如输入为 3、p 为 0.2：

$$
\tilde{x}=\begin{cases}0,&\text{概率 }0.2\\3/0.8=3.75,&\text{概率 }0.8\end{cases}\qquad\mathbb{E}[\tilde{x}]=0.2\times0+0.8\times3.75=3
$$

这保持的是期望，不保证每次刚好丢掉指定比例的元素。例如对 16 个全 1 元素使用 `p=0.5`，输出元素为 0 或 2，但零的数量不一定恰好是 8。

在训练模式外面加 `no_grad()`，随机失活仍然发生；切换到 `eval()` 后，输入原样通过，不再置零或缩放。

Dropout 没有可训练参数。它通过训练时随机遮掉部分特征，减少对固定特征组合的依赖。是否改善验证表现，需要实验判断，不能仅凭训练 Loss 更高或更低下结论。

## LayerNorm：样本统计与可训练参数要分开

**LayerNorm** 调整隐藏特征的数值尺度。对 $\mathbf{X}\in\mathbb{R}^{B\times D}$ 使用 `nn.LayerNorm(D)`，每个样本独立沿最后一个特征维计算均值和方差：

$$
\mu_i=\frac1D\sum_{j=1}^{D}X_{ij},\qquad
\sigma_i^2=\frac1D\sum_{j=1}^{D}(X_{ij}-\mu_i)^2
$$

$$
\tilde{X}_{ij}=\frac{X_{ij}-\mu_i}{\sqrt{\sigma_i^2+\varepsilon}}
$$

$i$ 是样本索引，$j$ 是特征索引。$\varepsilon>0$ 用于数值稳定，对应代码中的 `eps`：

```python
mean = X.mean(dim=-1, keepdim=True)                 # [B, 1]
variance = ((X - mean) ** 2).mean(dim=-1, keepdim=True)  # [B, 1]
normalized = (X - mean) / torch.sqrt(variance + eps) # [B, D]
```

这里方差按特征数 D 求平均，没有使用 D-1。`keepdim=True` 保留统计维度，确保每行减去自己的均值。

在 gamma 为 1、beta 为 0，且 eps 很小时，三行输入的结果近似为：

$$
\begin{bmatrix}1&2&3\\10&20&30\\5&5&5\end{bmatrix}\quad\longrightarrow\quad\begin{bmatrix}-1.2247&0&1.2247\\-1.2247&0&1.2247\\0&0&0\end{bmatrix}
$$

前两行的偏差和标准差按相同比例变化，尺度基本抵消；因为 eps 存在，它们不是严格完全相同。第三行没有特征差异，减均值后全为零。标准化不会凭空产生差异，也不能笼统地说所有输出的方差都一定为 1。

完整 LayerNorm 还包含可学习的逐元素缩放和平移：

$$
\mathbf{y}_i=\tilde{\mathbf{x}}_i\odot\boldsymbol{\gamma}+\boldsymbol{\beta}
$$

这里 $\tilde{\mathbf{x}}_i$ 是标准化后的第 $i$ 个样本。对于 `nn.LayerNorm(3)`，$\boldsymbol{\gamma},\boldsymbol{\beta}\in\mathbb{R}^{3}$，代码中的 shape 都是 `[3]`，默认分别初始化为全 1 和全 0。它们对应 `.weight` 和 `.bias`，共六个参数元素。

必须区分两类量：均值和方差由每个样本即时计算；gamma 和 beta 跨样本共享，由训练学习。batch 从 3 增加到 100，参数量仍然是六个。

加入缩放和平移后，最终输出不再保证均值为零。固定的 gamma、beta 也不能普遍恢复每个输入原本的均值和尺度。这一层提供的是对标准化特征的可学习调整。

## 优化器保存的历史，不是当前梯度

普通 SGD 的封装与手写更新逐参数一致。但当优化器加入动量和自适应统计以后，它还需要跨步骤保留自己的状态。

先看无阻尼、无 Nesterov 的 SGD 动量：

$$
\begin{aligned}\mathbf{u}_t&=\mu\mathbf{u}_{t-1}+\mathbf{g}_t\\\boldsymbol{\theta}_t&=\boldsymbol{\theta}_{t-1}-\eta\mathbf{u}_t\end{aligned}
$$

使用梯度序列 `[2, -1, 2, -1]`、动量系数 0.9 时，动量依次为 `[2, 0.8, 2.72, 1.448]`。第二步当前梯度已经为负，动量仍为正，因此更新还保持之前的方向。

上式中 $\mu$ 是动量系数，$\mathbf{u}_t$ 是累计动量，$\mathbf{u}_0=\mathbf{0}$。**Adam** 则保存两组指数移动平均，初始值均为零：

$$
\begin{aligned}\mathbf{m}_t&=\beta_1\mathbf{m}_{t-1}+(1-\beta_1)\mathbf{g}_t\\\mathbf{v}_t&=\beta_2\mathbf{v}_{t-1}+(1-\beta_2)(\mathbf{g}_t\odot\mathbf{g}_t)\end{aligned}
$$

$\mathbf{m}_t$ 综合历史梯度方向，$\mathbf{v}_t$ 记录梯度的平方尺度，避免正负梯度互相抵消。**二阶原点矩不是方差**：这里没有先减去梯度均值。$\beta_1$ 和 $\beta_2$ 控制两组历史统计的衰减速度。

从零初始化会让早期平均值偏小。假设梯度始终为 2，beta1 为 0.9，前两步 m 为 0.2 和 0.38。第二步实际梯度的权重之和只有 `0.09 + 0.1 = 0.19`，所以用 `0.38 / 0.19` 得到修正后的 2。

一般形式为：

$$
\begin{aligned}\hat{\mathbf{m}}_t&=\frac{\mathbf{m}_t}{1-\beta_1^t},\qquad\hat{\mathbf{v}}_t=\frac{\mathbf{v}_t}{1-\beta_2^t}\\\boldsymbol{\theta}_t&=\boldsymbol{\theta}_{t-1}-\eta\frac{\hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t}+\varepsilon}\end{aligned}
$$

偏差修正处理零初始化的影响，不会抹去历史平滑，也不代表结果等于当前梯度。梯度序列 `[2, 4, -1, 3]` 对应的修正一阶平均约为 `[2, 3.0526, 1.5572, 1.9767]`。

**上式中的除法和平方根都逐元素进行，不涉及矩阵求逆。** 公式用展平向量表示全部参数；实现中若某个参数 Tensor 是 `[32, 16]`，它的梯度和两组历史统计也都是 `[32, 16]`，每个参数元素维护自己的尺度。

还可以用成比例的梯度检查自适应缩放：若两组梯度历史始终相差十倍，使用相同超参数并从零初始化历史统计，忽略 eps 的影响时，两组自适应更新量相同。原因是：分子的 m_hat 放大十倍，分母的平方根也放大十倍，基本抵消。这依赖整个梯度历史成固定比例，不意味着任意两个参数的更新量都相同。

因此，`zero_grad()` 应清除当前 `.grad`，不能清除 m 和 v。优化器也应在训练循环外创建，否则历史会反复重置。

## AdamW 把参数衰减从历史统计里分离出来

在普通无动量 SGD 中，加入 **L2 惩罚项**后：

$$
J(\boldsymbol{\theta})=L(\boldsymbol{\theta})+\frac{\lambda}{2}\lVert\boldsymbol{\theta}\rVert_2^2,\qquad
\nabla J=\nabla L+\lambda\boldsymbol{\theta}
$$

这里采用 $\lambda/2$ 的系数，使惩罚项的梯度恰好为 $\lambda\boldsymbol{\theta}$。代入 SGD 更新式：

$$
\boldsymbol{\theta}_t=(1-\eta\lambda)\boldsymbol{\theta}_{t-1}-\eta\mathbf{g}_t
$$

其中 $\mathbf{g}_t$ 是任务损失的梯度。因此，在这个条件下，L2 惩罚等价于先按比例缩小参数，再应用任务梯度更新。

但 Adam 会对输入梯度计算历史平均和自适应缩放，L2 项也会跟着进入这些处理，所以通常不再等价于直接按比例缩小参数。

**AdamW 将权重衰减与自适应梯度更新分开**：$\mathbf{m}_t$、$\mathbf{v}_t$ 只接收任务梯度，权重衰减系数 $\lambda$ 单独作用于参数。

$$
\boldsymbol{\theta}_t=(1-\eta\lambda)\boldsymbol{\theta}_{t-1}-\eta\frac{\hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t}+\varepsilon}
$$

实验中，一个参数初始为 2，任务梯度为 -0.1，学习率为 0.01，衰减系数为 0.1。只看第一次更新并忽略很小的 eps：

| 方式 | 计算过程 | 更新后参数 |
| --- | --- | --- |
| Adam + L2 | 总梯度为 -0.1 + 0.1 × 2 = 0.1，交给 Adam | 1.99 |
| AdamW | Adam 的任务更新增加 0.01，独立衰减减少 0.002 | 2.008 |

AdamW 的结果增大，并不说明衰减没有生效。衰减确实减小了参数，只是任务更新的增大量更大。

两种更新方式的差异也体现在优化器的一阶历史中：Adam + L2 保存的是混合后的梯度历史，AdamW 保存的是任务梯度历史。

## 用验证曲线判断，Dropout 到底改变了什么

下面的对照示例使用 36 个训练样本、300 个验证样本，以及两个 64 维隐藏层。两组实验共享数据、初始权重和全量训练顺序，只改变 Dropout 概率。这些结果用于说明如何阅读验证曲线；由于未附完整的数据生成代码和随机种子，表中数值不作为可独立复现的基准。

训练和验证指标都在每轮更新后切到评价模式重新计算，这样不会把训练阶段的随机失活混入指标比较。

| 设置 | 第 200 轮训练 Loss | 第 200 轮验证 Loss | 最低验证 Loss | 最佳轮次 |
| --- | --- | --- | --- | --- |
| 不使用 Dropout | 0.0007 | 1.8062 | 0.3033 | 6 |
| Dropout p=0.5 | 0.0560 | 0.8253 | 0.3007 | 8 |

基线模型几乎完全拟合训练集，但验证 Loss 随后持续上升。Dropout 减轻了后期的过拟合，却没有让它消失。

比较时应使用一致的模型选择规则：两组各自最低的验证 Loss 很接近，主要区别在后期退化程度。不能只拿基线最后一轮和 Dropout 最佳一轮比较，也不能根据一个随机种子证明 Dropout 普遍更好。

多分类的准确率和交叉熵也可能不同步。另一个较容易的数据集上，验证准确率第 5 轮就达到 100%，交叉熵仍从 0.0764 降到 0.0152。模型没有多分对样本，而是在已分对的样本上继续提高正确类别概率。

对于同一数据集，更小的平均交叉熵表示更好的平均负对数概率表现，不保证每个样本的正确类别概率都提高，也不能直接推出其他数据上的可靠性。

## 最佳模型必须是独立快照

验证曲线最低点出现在中间，就需要保存那一轮的参数。需要注意，下面的赋值只取得状态映射：

```python
best_state = model.state_dict()
```

**不能保证得到独立快照。**`state_dict()` 返回的映射包含对模型参数和持久缓冲区的引用，后续训练可能让其中的数值一起变化。

正确的内存快照方式是：

```python
if val_loss < best_val_loss:
    best_val_loss = val_loss
    best_epoch = epoch
    best_state = copy.deepcopy(model.state_dict())
```

训练结束后恢复：

```python
model.load_state_dict(best_state)
model.eval()
```

恢复参数本身不会切换模型模式。用于评价时仍要进入 eval，并关闭梯度记录。

在基线实验中，最后一轮验证 Loss 为 1.806248、准确率为 78.3%；恢复第 6 轮后，Loss 回到 0.303314，准确率为 88.3%。恢复后的 Loss 与保存时的值一致，这是检查快照是否真正有效的直接证据。

这个过程是训练完整轮数后选择最佳参数，不是提前停止训练。如果要把训练任务中断后精确接着跑，仅有模型参数也不够，还需要优化器状态、步数，以及相应的随机状态等信息。

## 最终实验：从 mini-batch 训练到独立测试

最后把这些机制放进一个三分类实验，配置在测试前确定：

| 项目 | 设置 |
| --- | --- |
| 数据 | 三个二维高斯簇，每类 120 个样本 |
| 划分 | 每类 60 个训练、30 个验证、30 个测试样本 |
| 模型 | 2 → 32 → 32 → 3，两层隐藏激活为 ReLU |
| Dropout | 第二个隐藏层后，p=0.2 |
| 优化器 | AdamW，lr=0.01，weight_decay=0.01 |
| 训练 | batch_size=32，共 80 轮 |
| 模型选择 | 验证交叉熵最低的轮次 |

模型共有 1251 个参数元素。180 个训练样本每轮分成六批，最后一批有 20 个样本。评价时按样本累加损失，避免最后一批权重失真。

该模型使用 Linear、ReLU 和 Dropout，不包含 LayerNorm。前面的 LayerNorm 示例用于单独说明标准化统计与可训练参数的区别。

流程中的关键片段如下，`evaluate` 内部负责 eval、no_grad，以及按样本汇总交叉熵和准确率：

```python
best_loss = float("inf")
best_state = None

for epoch in range(1, num_epochs + 1):
    train_one_epoch(model, train_loader, optimizer)
    val_loss, val_accuracy, _ = evaluate(model, val_loader)

    if val_loss < best_loss:
        best_loss = val_loss
        best_epoch = epoch
        best_state = copy.deepcopy(model.state_dict())

torch.save(best_state, checkpoint_path)
restored_model = Classifier()
restored_model.load_state_dict(
    torch.load(checkpoint_path, map_location="cpu", weights_only=True)
)

# 先确认恢复后的验证 Loss 与记录一致，再进行唯一一次测试评价。
test_loss, test_accuracy, confusion = evaluate(restored_model, test_loader)
```

## 模型交付需要保留哪些信息

最终需要解释的不只是一次 forward 和 backward，还包括：每批梯度何时清除，优化器历史怎样延续，评价时哪些随机行为被关闭，哪一个验证结果决定了模型选择。

验证集没有参与反向传播，但它参与了最佳轮次的选择。因此恢复出的最佳验证成绩仍然是选择过程的一部分，需要独立测试集完成最终评价。

用于推理时，需要匹配的模型结构、选中的参数快照和正确的评价模式；用于继续训练时，还要恢复优化器等训练状态；用于解释实验结果时，则需要记录数据划分、配置、模型选择规则和最终测试指标。

这三类信息分别回答“如何运行模型”“如何继续训练”和“为什么选择这个模型”。后续换成 Transformer 等结构时，这些职责仍然适用，变化主要在模型的前向计算、数据组织和训练目标。
